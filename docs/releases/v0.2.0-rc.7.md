# z2000 0.2.0-rc.7

This release candidate fixes resolution-reduced decoding on more than one
thread, which rc.5 and rc.6 rejected with `InvalidCodestream` on most images
taller than a few hundred rows. It is rc.6 with that fix and one encoder
speed-up; it changes no format or CLI behaviour, and every stream that
rc.6 decoded gives the same samples.

## Fixes

- **Threaded reduced decodes.** A decode with `--reduce N` (or
  `resolution_reduction` in the Zig API) on two or more threads failed with
  `InvalidCodestream` once a component plane, or a tile of one, was tall
  enough for the block coverage check to cut it into more than one row
  band; on one thread it decoded. A band that started below the rows the
  reduced image needs got a reversed row range: an integer overflow in safe
  builds, a spurious rejection in release builds. Such a band now only
  marks its blocks, so overlapping blocks are still rejected there. It was
  reported against rc.6 with a 2761x3870 Grok 9/7 RGB JP2 in 1024x1024
  tiles, which now decodes identically on 1, 2, 4, and 20 threads at
  `--reduce` 1 to 5, with and without `--region`; a unit test compares
  2-, 4- and 8-thread reduced decodes with one thread. Unreduced decodes
  were not affected. Until upgrading, `--threads 1` avoids it.

## Faster Lossless Encode

- On more than three threads the lossless encoder transforms only the first
  5/3 level before Tier-1 and codes that level's detail blocks, three
  quarters of the image, while the coarser levels are still being
  transformed (about 1 ms at 20 threads on the i5-14500). Codestreams are
  byte-identical to rc.6's. The rc.6 benchmark checkpoint in
  `docs/benchmarks.md` otherwise stands.

## Release Process

- As for rc.6, every archive was built and tested on a local machine:
  native Windows gates, and the Linux x86-64 and RISC-V 64 ReleaseFast suites
  in a Linux container (RISC-V under QEMU), with the official T.803 streams
  included in the corpus run (`tools/release_local.ps1`). The interop
  scripts against Kakadu 8.4.1, OpenJPEG 2.5.4, and Grok 20.4.19 passed
  before it.
- **No macOS archive** is published for this candidate: hosted Actions
  minutes, which the native macOS build needs, are exhausted, and a
  cross-built binary could not be tested here. macOS users can build from
  source with Zig 0.17.

## Release Candidate Policy

The CLI and Zig API remain unstable before 1.0. This is not a general JP2/JPX,
camera RAW, or HDR converter. Each input adapter has a deliberately narrow
documented envelope; old-style or progressive JPEG, CCITT, LZMA, and ZSTD
TIFF compression, Adam7 PNG, CFA/demosaicing, compressed or tiled EXR,
general ICC transforms, extended XMP, and semantic metadata rewriting remain
unsupported. JP2 metadata payloads are preserved but are not yet restored into
TIFF output.

The project's 100/100 ISO engineering scorecards are internal coverage tools,
not formal ISO conformance certification; passing the T.803 streams is
evidence, not certification. The binaries are unsigned; verify the platform
archive against `SHA256SUMS`. Every archive contains identical `z2000` and
`z2k` executables for the long and short command names.
