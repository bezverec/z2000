# z2000 0.2.0-rc.4

This release candidate fixes the quality layers of every layered stream that
rc.3 wrote, decodes every JPEG 2000 Part 1 sample precision from 1 to 38 bits,
passes all seven ITU-T T.803 profile-1 streams in addition to the sixteen
profile-0 ones, and adds a native encoder (`zraw-to-j2k`) for any Part 1
component layout.

## Fixes Since 0.2.0-rc.3

- **Quality layers decode correctly.** A layer that ended inside a block's
  continuous codeword carried only the bytes the MQ coder had already
  emitted, so every decoder (z2000, Kakadu, OpenJPEG, Grok) reconstructed the
  end of that pass wrongly: layer 1 of a five-layer RGB stream differed in
  649297 samples by up to 110 levels. Each pass boundary now records the
  shortest prefix that decodes it exactly. Only intermediate layers were
  affected; full streams and BYPASS/TERMALL segment ends were always exact.
  Layered files written by rc.3 keep the defect in their intermediate layers
  and should be re-encoded if those layers matter.
- **POC follows ISO/IEC 15444-1 A.6.6.** A tile's own POC replaces the
  main-header POC instead of extending it, at most one POC marker may appear
  in a header, and a tile that uses POC must carry one in its first
  tile-part. A single-tile POC in a later tile-part header now decodes, and
  R, L, and C tile-parts work under any POC schedule.
- PCRL and CPRL streams whose tiles are not aligned to the precinct grid,
  PPT streams ending in empty packets, JP2 files with QCC for only some
  components, and tile coding overrides in every progression order decode.

## Broader Part 1 Decode

- **Every Part 1 precision.** Reversible components of 30 to 38 bits, and
  any component whose bands need more than 31 magnitude bitplanes, decode
  through 64-bit coefficients up to the Part 1 ceiling, block-parallel like
  the 32-bit path. None of the codecs we compare against decode above 30
  bits.
- All seven T.803 profile-1 streams pass beside the sixteen profile-0 ones.
- The native decoder (`j2k-to-pgx`, `j2k-to-zraw`) applies ICT as well as
  RCT, accepts component-local coding together with component subsampling
  and on multi-tile streams, and applies RCT when the other components
  differ in precision or sampling.

## New: Native Encoder

`zraw-to-j2k` encodes a canonical ZRAW reversibly into a raw codestream:

- any Part 1 component layout: up to 16384 components, each signed or
  unsigned with its own precision from 1 to 38 bits and its own subsampling,
  on a reference grid with any origin, with component registration (CRG);
- one tile or a tile grid encoded in parallel, RCT, every progression order,
  POC, R/L/C/P tile-parts, TLM, PPM/PPT, SOP/EPH, and every code-block style;
- per-component levels, code-block size, precincts, and style (COC);
- Maxshift regions of interest whose region decodes losslessly from the
  first layer alone;
- rate-targeted layers by global PCRD (`--rates`).

At 8 and 16 bits its output is byte for byte that of the existing RGB,
planar, gray, and sampled encoders. Kakadu 8.4.1 decodes its streams exactly
within Kakadu's own precision; OpenJPEG 2.5.4 decodes ROI streams exactly
except with BYPASS, which it misdecodes even from Kakadu's own encoder (see
`docs/reference_tools.md`).

## Release Process

- As for rc.3, every archive was built and tested on a local machine:
  native Windows gates, and the Linux x86-64 and RISC-V 64 ReleaseFast suites
  in a Linux container (RISC-V under QEMU), with the official T.803 streams
  included in the corpus run (`tools/release_local.ps1`).
- **No macOS archive** is published for this candidate: the hosted build that
  produced it is unavailable, and a cross-built binary could not be tested
  here. macOS users can build from source with Zig 0.17.

## Release Candidate Policy

The CLI and Zig API remain unstable before 1.0. This is not a general JP2/JPX,
camera RAW, or HDR converter. Each input adapter has a deliberately narrow
documented envelope; old-style or progressive JPEG, CCITT, LZMA, and ZSTD
TIFF compression, Adam7 PNG, CFA/demosaicing, compressed or tiled EXR,
general ICC transforms, extended XMP, and semantic metadata rewriting remain
unsupported. JP2 metadata payloads are preserved but are not yet restored into
TIFF output. Irreversible 9/7 components are decoded up to 24 bits.

The project's 100/100 ISO engineering scorecards are internal coverage tools,
not formal ISO conformance certification; passing the T.803 streams is
evidence, not certification. The binaries are unsigned; verify the platform
archive against `SHA256SUMS`. Every archive contains identical `z2000` and
`z2k` executables for the long and short command names.
