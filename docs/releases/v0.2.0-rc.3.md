# z2000 0.2.0-rc.3

This release candidate fixes a regression in `0.2.0-rc.2` that rejected
JPEG 2000 streams declaring a Part 1 profile, decodes ordinary rate-truncated
reversible files that rc.2 refused, and passes all sixteen ITU-T T.803
profile-0 conformance streams.

## Fixes Since 0.2.0-rc.2

- **Profile streams decode again.** rc.2 rejected every codestream with a
  nonzero `Rsiz`, so Profile 0/1, digital cinema, broadcast, and IMF streams
  (for example OpenJPEG `-cinema2K`/`-IMF` or Kakadu `Sprofile` output) failed
  with `UnsupportedPayload`. These profiles only restrict Part 1 syntax and
  now decode like unrestricted streams; Part 2, CAP, PRF, and reserved
  declarations still fail closed.
- **Rate-truncated reversible files decode.** A reversible stream whose
  encoder truncated its layers, such as Kakadu `Creversible=yes -rate N` or
  OpenJPEG's default output with `-r N`, can reconstruct slightly out of
  range; rc.2 rejected it with `SampleOutOfRange`. Only a decode in which
  every code block provably carries all its coding passes is now treated as
  exact; every other decode clamps to the component range, and the output
  matches Kakadu exactly. Corrupt complete streams still fail closed.
- Ordinary Kakadu streams whose COD level count is below one component's
  COC no longer fail as `InvalidCodestream`.

## Broader Part 1 Decode

- All 16 T.803 profile-0 streams pass; rc.2 as shipped passed only the three
  that declare no profile. New: multipart POC under a main RLCP progression
  (`p0_07`), up to 16384 components with two-byte component selectors above
  256 (`p0_13`, 257 components), a main QCD shared across components with
  different level counts (`p0_05`, `p0_08`), and RCT on the native path for
  any component count.
- The native decoder (`j2k-to-pgx`, `j2k-to-zraw`) applies RCT to components
  0..2 and mixes 5/3 and 9/7 components in single-tile streams.

## Release Process

- Every archive in this release was built and tested on a local machine:
  native Windows gates, and the Linux x86-64 and RISC-V 64 ReleaseFast suites
  in a Linux container (RISC-V under QEMU), with the official T.803 streams
  included in the corpus run. `tools/release_local.ps1` records the
  procedure.
- **No macOS archive** is published for this candidate: the hosted build that
  produced it is unavailable, and a cross-built binary could not be tested
  here. macOS users can build from source with Zig 0.17.

## Release Candidate Policy

The CLI and Zig API remain unstable before 1.0. This is not a general JP2/JPX,
camera RAW, or HDR converter. Each input adapter has a deliberately narrow
documented envelope; old-style or progressive JPEG, CCITT, LZMA, and ZSTD
TIFF compression, Adam7 PNG, CFA/demosaicing, compressed or tiled EXR,
general ICC transforms, extended XMP, and semantic metadata rewriting remain
unsupported. JP2 metadata payloads are preserved but are not yet restored into
TIFF output.

The project's 100/100 ISO engineering scorecards are internal coverage tools,
not formal ISO conformance certification; passing the T.803 streams is
evidence, not certification. The binaries are unsigned; verify the platform
archive against `SHA256SUMS`. Every archive contains identical `z2000` and
`z2k` executables for the long and short command names.
